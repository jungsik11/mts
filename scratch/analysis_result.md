## 종목 가격이 -100%를 찍는 이유 분석 결과

확인 결과, 현재 MTS 시스템 내 주식 가격 결정 및 주문 처리 로직에 **상하한가(가격 제한폭) 안전장치가 없어서** 발생하는 현상입니다.
구체적으로 다음과 같은 과정으로 인해 -100% (-99.99%) 하락이 발생합니다.

### 1. 팻핑거(Fat Finger) 및 상하한가 제한 부재
`trading_server_kt`의 `TradeManager.kt`를 보면, 주문 요청이 들어왔을 때 가격이 0보다 큰지(`order.price <= 0`)만 검사할 뿐, **전일 종가(basePrice) 대비 +/- 30% 와 같은 상하한가 검증 로직이 존재하지 않습니다.**
따라서 사용자가 실수로 (또는 고의로) 100,000원짜리 주식을 10원에 파는 매도 주문을 넣더라도 시스템은 이를 그대로 정상 주문으로 받아들입니다.

### 2. 주문 체결 방식 (기존 호가 우선)
`OrderBook.kt`의 체결 로직을 보면 다음과 같습니다.
```kotlin
price = price, // Execution price is the existing order's price
```
사용자가 10원이라는 극단적으로 낮은 매도 주문을 넣었고, 호가창에 이를 받아줄 기존 매수 주문이 없다면 이 주문은 호가창에 등록됩니다.
이후 트레이딩 봇(또는 다른 사용자)이 정상적인 가격(예: 100,000원)으로 매수 주문을 넣으면, 시스템은 **이미 호가창에 대기 중이던 사용자의 10원짜리 매도 주문과 매칭**시킵니다. 체결 가격은 기존에 대기중이던 주문 가격인 **10원**으로 결정됩니다.

### 3. 시장가 반영 및 -100% 계산
10원에 체결이 일어나면 `updateMarketPrice` 함수가 호출되어 현재 시장가를 10원으로 업데이트합니다.
```kotlin
val totalChangePercent = if (basePrice != 0.0) ((executionPrice - basePrice) / basePrice) * 100.0 else 0.0
val change_percent = Math.round(totalChangePercent * 100.0) / 100.0
```
만약 전일 종가(`basePrice`)가 100,000원이었다면, 변화율은 `(10 - 100000) / 100000 * 100 = -99.99%`가 됩니다.
여기서 `Math.round`에 의해 소수점 둘째 자리까지 반올림되면서 화면에는 정확히 **-100.0%**로 표시되는 것입니다.

### 4. 트레이딩 봇의 추종
트레이딩 봇(`trading_bot.py`)은 무작위로 주문을 넣을 때 현재가(`current_price`)를 기준으로 +/- 2% 내외의 주문을 생성합니다. 한 번 체결가가 10원으로 떨어지면, 이후 봇들은 이 10원을 기준으로 주문을 넣기 때문에 주가가 계속 바닥을 기게 됩니다.

---
### 💡 해결 방안 제안
이 문제를 해결하려면 `TradeManager.kt`의 `placeOrder` 단계에서 **주문 가격이 전일 종가(base_price) 기준 상하한가(예: ±30%)를 벗어나는 경우 주문을 거절(Reject)하는 로직**을 추가해야 합니다. 필요하시다면 제가 이 보호 로직을 바로 코드로 구현해 드릴 수 있습니다. 추가하시겠습니까?
